# Torreto's Garage — scrollytelling-движок

Пять сцен и четыре видеоперехода. Вьюпорт зафиксирован: один жест — один шаг.

```bash
npm install            # playwright, pngjs, pixelmatch (только для инструментов)
npm run build:video    # ffmpeg: media/1.mp4, 1.rev.mp4, 2.mp4, 2.rev.mp4 + manifest.json
npm run build:clips    # ffmpeg: клипы переходов для телефонов media/clips/ + стоп-кадры media/stills/
npm run serve          # http://localhost:5173  (статический сервер с HTTP Range)
npm test               # автотест механики (autotest.html + сценарии в реальном Chrome)
npm run pixel          # пиксельная сверка 1440×810 @2x с Frame 9–13.png
npm run tunnel         # публичная HTTPS-ссылка для телефона (Cloudflare Quick Tunnel, нужен запущенный serve)
```

Ссылка туннеля вида `https://…trycloudflare.com` живёт, пока запущен `cloudflared`; после перезапуска адрес будет новым.

Страницу `autotest.html` можно открыть и вручную (`http://localhost:5173/autotest.html`): она прогоняет сценарии на живом лендинге в iframe и показывает результат.

## Как собрана видеопоследовательность

Кадры покоя найдены перебором: каждый макет сравнивался со всеми кадрами обоих роликов (RMSE).

| Сцена | Макет | Кадр покоя |
|---|---|---|
| 1 Hero | Frame 9 | `1.mp4` #0 |
| 2 Engineering | Frame 10 | `1.mp4` #120 (последний) |
| 3 Brakes & Suspension | Frame 11 | `2.mp4` #118 |
| 4 Maintenance | Frame 12 | `2.mp4` #238 |
| 5 Booking | Frame 13 | `2.mp4` #360 (последний) |

Особенности исходников:

- На деле `1.mp4` длится 5 с, а `2.mp4` — 15 с, то есть наоборот относительно ТЗ.
- `1.mp4` имеет размер 1280×704. Это обрезка того же кадра 1280×720, с которого начинается `2.mp4` (лучшее совпадение при сдвиге 8 px). При сборке ролик дополняется до 720 через `pad` + `fillborders`, поэтому кадр героя совпадает с макетом.
- Между синим дымом (конец `1.mp4`) и началом `2.mp4` нет соединяющих кадров. Интервал сцены 2 играет `2.mp4` с кадра 0, а склейка смягчена растворением 0.6 с (`blend` в конфиге). Остальные стыки — кадр в кадр. Прямой и реверсный файлы на точках стыка отличаются на уровне PSNR 49–54 дБ, то есть визуально идентичны.

## Стартовый постер и мобильная версия

- **Постер `top.jpeg`.** При загрузке сайт стоит на резком `top.jpeg` (сцена 1). Первый скролл или свайп растворяет его в видео за 0.7 с, при возврате на сцену 1 постер проявляется снова. Постер — чистая версия кадра 0 из `1.mp4`: сопоставлен численно (тот же масштаб, вертикальный сдвиг 49.3% в 16:9-прямоугольнике `cover`), поэтому растворение бесшовное на экране любой формы. Автоинтро выключено (`intro.enabled` в конфиге).
- **Видео для телефонов.** Отдельный набор `media/m/` (CRF 24): 9.9 МБ вместо 19.2 МБ. Сразу грузится только первый ролик, остальные — по мере приближения к ним; на десктопе всё догружается после загрузки страницы. Готовность видео определяется по метаданным: iOS Safari не буферизует кадры до первого seek/play.
- **Портрет (≤ 760 px).** Полноэкранная сцена на 390-px сетке: шапка из логотипа, `[ ES | RU ]` и двух кнопок (запись и меню-поп-ап); заголовок, одна приборная панель, карточки 2×2, счётчик; отступы под вырез и домашнюю полосу iPhone (safe-area). Для низких экранов (≤ 700 px по высоте) — более плотная раскладка. Поп-ап — на весь экран, листается пальцем.
- **Альбомная ориентация телефона.** Сохраняется композиция 16:9, мелкие HUD и подписи скрыты, шапка из крупных кнопок.
- **Свайпы** вверх/вниз — одна сцена за жест (порог 40 px), во время перехода игнорируются, при открытом поп-апе страница не листается.

## Звук: микшер Burmester (High-End)

Кнопка в шапке (на телефоне — кнопка с динамиком) одним нажатием включает и выключает оба канала. Сам по себе звук не стартует никогда.

- **Музыка** — основной слой. Плавно нарастает за 1.6 с и звучит фоном на уверенной громкости.
- **SFX Porsche** — второй слой ([porsche-sfx.js](porsche-sfx.js)), синтезируется в реальном времени. При включении звука — стартер и прогазовка. На каждый скролл вперёд — разгон с переключением передачи, рык на 8600 об/мин, хлопки на сбросе газа и лёгкий визг резины. Назад — торможение с перегазовками. На дрифте в гараже (2→3) визг длиннее. Рык подстраивается под длительность перехода.
- **Баланс**: шина SFX = 0.3 от музыки, пиковый рык примерно на 1.5 дБ тише средней громкости трека. Во время рыка музыка приглушается до 80 % и возвращается через 0.6 с после него. Общий компрессор на мастере сглаживает пики.
- Колесо мыши или ↑/↓ над модулем меняют общую громкость обоих слоёв.
- Настройки — `audio.sfx` в [scenes.config.js](scenes.config.js): `level`, `duck`, `driftTransition`, `enabled`.

## Тема NIGHT / DAY (Matrix LED)

- Переключатель Matrix LED в шапке (на телефоне — кнопка ☾/☀) меняет тему всего интерфейса: шапки, панелей HUD, карточек, текстов, чертежа и поп-апов.
- **Night** — матовый чёрный и графит, оранжевые LED-акценты, светлый текст. **Day** — платиново-серебристые поверхности и графитовый текст; оранжевый и зелёный сделаны глубже, чтобы мелкий текст держал контраст ≥ 4.5 : 1. Под заголовками и категориями лежат светлые вуали поверх видео, чтобы тёмный текст читался на любом кадре.
- Смена темы идёт со световой LED-развёрткой по экрану и плавным переходом цветов. Выбор сохраняется в `localStorage` (`torreto.theme`) и применяется до первой отрисовки, без мигания. Принудительно — `?theme=day` / `?theme=night`.

## Телефоны: клиповый режим видео

На телефонах (`data-video-mode="clips"`) видео не перематывается и не протягивается никогда:

- Каждый переход — отдельный клип (`media/clips/t{i}.mp4` и `t{i}.rev.mp4`, ~0.9 МБ), который всегда играется с первого кадра до последнего обычным `video.play()`.
- Клипы заранее скачиваются целиком в память (`blob:`): оба соседних для текущей сцены и ещё по одному шагу вперёд и назад. Воспроизведение не ждёт сети, одновременно живут максимум 2–3 декодера.
- Кадр покоя сцены — точный стоп-кадр (`media/stills/s{n}.jpg`, для сцены 1 — `top.jpeg`). В покое видео не декодируется вообще. Стоп-кадр и первый/последний кадр клипа совпадают (PSNR 45–46 дБ), поэтому стыки незаметны.
- `play()` вызывается синхронно внутри обработчика жеста. Если iOS всё же отказал (режим энергосбережения), `play()` повторяется на отрыве пальца, а следующие свайпы сами стартуют на отрыве. Последний запасной вариант — мягкое растворение между стоп-кадрами, а не покадровая протяжка.
- Единственная запись `currentTime` на телефоне — перемотка уже доигравшего скрытого клипа на 0, в покое. Автотест проверяет, что во время переходов записей ноль.

На десктопе остаётся прежний режим с отрезками длинных файлов (вперёд и реверс).

## Телефоны: производительность

- Над видео нет `backdrop-filter` (он пересчитывает размытие каждый кадр) — вместо него плотное «стекло». В появлении блоков нет анимации размытия; фоновые анимации стоят на паузе, пока играет видео.
- Тяжёлые плашки (HUD, чертёж, карточки) показываются ~3.5 с после прихода на сцену и скрываются (`visibility: hidden`, не просто прозрачность). Во время видео их нет совсем; касание экрана возвращает их. Длительность — `mobilePanels.holdMs` в конфиге.
- Свайп срабатывает во время движения пальца, как только тот прошёл 40 px, а не после отрыва.
- Пока сцена стоит, видео соседних переходов заранее перематываются на свой первый кадр, поэтому свайп стартует без ожидания перемотки по сети.

## Шкала UI (25 с)

| Сцена | Интервал | Видео под экраном сцены |
|---|---|---|
| 1 | 0–5 с | постер `top.jpeg` → `1.mp4` 0 → 120 (по первому скроллу) |
| 2 | 5–10 с | `2.mp4` 0 → 118 |
| 3 | 10–15 с | `2.mp4` 118 → 238 |
| 4 | 15–20 с | `2.mp4` 238 → 360 |
| 5 | 20–25 с | финальный кадр |

- **Вперёд:** экран текущей сцены неподвижно держится, пока под ним идёт её 5-секундный отрезок, и в конце плавно сменяется экраном следующей сцены (старый гаснет за 0.35 с, новый проявляется со stagger).
- **Назад:** время возвращается в интервал предыдущей сцены, поэтому её экран показывается сразу, пока интервал отматывается к своему первому кадру.
- `autoAdvance: true` в конфиге — проиграть все 25 с подряд самостоятельно; скролл при этом продолжает работать.

## Поп-апы и язык

- Пункты меню открывают поп-ап с вкладками (←/→ переключают вкладки, ESC или клик по фону закрывают). Пока поп-ап открыт, скролл, клавиши и свайпы не листают сцены. Кнопки «Записаться» и «[ ЗАБРОНИРОВАТЬ ВИЗИТ ]» открывают вкладку «Контакты» с фокусом на форме.
- Контакты берутся из `content.config.js`. Незаполненные поля показываются как «не задано», а кнопка WhatsApp отключена. Отправка формы: `window.onBookingSubmit(data)`, если он задан; иначе WhatsApp с заполненным текстом, если указан номер; иначе — сообщение, что канал не подключён.
- `[ ES | RU ]` есть в шапке и внутри поп-апа. Исходный текст страницы — RU (как в макете); ES подставляется по словарю `i18n.js` (новый текст — новая строка словаря). Выбор запоминается в браузере, принудительно — `?lang=es`.
- Правая группа шапки (Matrix LED, звук) сдвинута относительно макета, чтобы поместился переключатель. Эти элементы помечены `data-pc-skip` и не участвуют в пиксельной сверке.

## Поведение

- **Вперёд** — нативное воспроизведение прямого файла от `in` до `out`. **Назад** — нативное воспроизведение реверсного файла (`ffmpeg reverse`) по зеркальному отрезку.
- **Протяжка `currentTime` через rAF** — только запасной режим: когда `play()` отклонён (тогда без скачка) или реверсный файл не загрузился.
- **Окончание перехода.** Видео останавливается за пол-кадра до `out` и доводится точным seek на середину кадра. На экране всегда лежит точный кадр покоя, статичных заглушек под видео нет.
- **Ввод.** Колесо, свайп и клавиши (↓ ↑ ← → PageUp/PageDown, Space/Shift+Space) работают одинаково. Новый жест засчитывается только после 180 мс тишины на этом канале. События во время перехода отбрасываются и в очередь не попадают; автоповтор клавиш игнорируется. На сценах 1 и 5 движение за край блокируется (событие `sceneedge`).
- **Таймауты.** Загрузка видео — 8 с, seek — 2.5 с. Сторож воспроизведения срабатывает при ожидаемом времени × 1.6 + 1.5 с; таймер подвисания буфера — 2 с. Если вкладку свернули, переход сразу доводится до финального кадра.
- **Если страница не может работать.** При `file://`, отсутствии конфига или падении движка вместо чёрного экрана показывается понятное текстовое объяснение. При `<noscript>` — тоже.
- **`prefers-reduced-motion`.** Переход становится растворением в кадр покоя, а UI просто проявляется.
- **Логотип** возвращает к сцене 1 по шагам: каждый переход проигрывается, сцены не пропускаются.

### Состояние и события

На `<html>` выставляются атрибуты `data-scene` (1–5), `data-state` (`boot | transition | idle | error`) и `data-direction` (`none | forward | backward`). Движок генерирует события `scenechange`, `transitionstart`, `transitionend` и `sceneedge` (`CustomEvent` с `detail`, всплывают от `<html>`).

> Имена `transitionstart` и `transitionend` совпадают с нативными событиями CSS-переходов, которые тоже всплывают до `<html>`. Отличайте их проверкой `e instanceof CustomEvent`.

```js
document.documentElement.addEventListener('scenechange', (e) => {
  if (e instanceof CustomEvent) console.log(e.detail.scene);
});
```

API для отладки — `window.TorretoEngine` (`scene`, `state`, `visible`, `stats`, `log`, `next()`, `prev()`, `walkTo(n)`). Query-параметры: `?scene=N` — открыть сразу сцену N, `?nointro`, `?static` — без анимаций, для пиксельной сверки.
